# Expense Tracker — web

The third client, alongside Android and iOS. React + TypeScript, talking to the same Firebase
project and reusing the domain layer from `shared/` compiled to Kotlin/JS.

```
shared/ ──(Kotlin/JS, binaries.library)──▶ npm package ──▶ React + TypeScript
                                                              │
                                                     Firebase JS SDK
                                                    (Auth + Firestore)
```

## What is reused, and what is new

**Reused, not reimplemented** — one copy, in `shared/commonMain`, so it cannot drift between the
three clients: the domain models, `Permissions` (the access rules), `ExpenseFilter` (the search
and filter predicate, amount matching included), `CategoryPresets` (the 22-entry catalogue),
`CategoryIcons` (the name→icon resolver), the spending-split calculators, the budget and goal
thresholds, the Indian currency formatting, and `SmsTransactionParser`.

**New here**: the UI, and the Firestore access layer built on the JS SDK.

**Inherited for free**: the entire permission model. `firestore.rules` is the only enforcement
on any client, so the web app cannot bypass what Android and iOS obey, and needed no rules
changes.

## First-time setup

The web app is a **separate app registration** in the existing Firebase project. It is not in
`google-services.json` or `GoogleService-Info.plist`, so this step cannot be skipped.

1. **Register a Web app.** Firebase console → Project settings → Your apps → Add app → Web.
   Copy the config values.

2. **Create `web/.env`** from the template:
   ```bash
   cp web/.env.example web/.env   # then fill in the values
   ```
   These values are public by design — they identify the project and authorise nothing.

3. **Authorise the domain** for sign-in. Firebase console → Authentication → Settings →
   Authorized domains. `localhost` is there by default; add your hosting domain before
   deploying, or Google sign-in fails with `auth/unauthorized-domain`.

4. **Enable the sign-in methods** you want under Authentication → Sign-in method:
   Email/Password and Google.

## Running it

The shared module must be compiled before the web app can resolve it:

```bash
./gradlew :shared:jsBrowserProductionLibraryDistribution   # from the repo root
cd web && npm install
npm run dev
```

Re-run the Gradle task after any change to `shared/`. `optimizeDeps.exclude` in
`vite.config.ts` keeps Vite from serving a cached copy of the old build.

```bash
npm run typecheck   # tsc --noEmit
npm run build       # tsc -b && vite build
```

## Deploying

```bash
./gradlew :shared:jsBrowserProductionLibraryDistribution
cd web && npm run build
cd .. && firebase deploy --only hosting
```

`firebase.json` rewrites every path to `index.html`, which the client-side router needs — without
it a reload on `/expenses` returns 404.

Note the CLI OAuth flow is blocked by Workspace policy on this account; rules have been
published from the console instead. Hosting deploys may hit the same wall, in which case build
locally and upload `web/dist` through the console.

## Three sharp edges

**1. Kotlin/JS will not export `Long`, a `commonMain` data class, or a `List` — and says so
only as a warning.** The build still succeeds, with the type silently degraded in the generated
`.d.ts`. So `shared/src/jsMain/.../web/WebBridge.kt` is a bridge layer — the direct counterpart
of `SharedBridge.swift` — that takes and returns plain JS objects, with epoch millis as
`number`. `shared/build.gradle.kts` sets `allWarningsAsErrors` for the JS target so that a
`Long` added to a signature fails the build instead of quietly breaking TypeScript.

**2. A member's unfiltered expense query is rejected, not filtered.** Firestore authorises a
`list` by proving every document it could return satisfies the rule, and an unfiltered query
cannot be proven. `observeExpenses` therefore picks its query shape from the role: one listener
for a manager, two (`scope == 'shared'` and `addedBy == uid`) merged by id for everyone else.
A member seeing an *empty* list rather than a partial one is the signature of getting this
wrong — or of an expense row with no `scope` field.

**3. Time is epoch milliseconds, never a Firestore `Timestamp`.** Writing a `Timestamp` crashes
Android with `Field 'date' is not a java.lang.Number`. All three clients read either form for
compatibility; all three must only ever write millis.

## Deliberately not on the web

- **Automatic SMS import.** No browser can read an SMS inbox — the same limitation iOS has.
  Pasting a bank alert into the expense form runs the identical shared parser.
- **Recurring generation.** Rules are created and edited here, but the expenses are generated by
  whichever mobile app opens next. A browser tab is not a reliable scheduler, and a third writer
  racing Android and iOS against the same `lastGeneratedDate` would duplicate rows.
- **Biometric unlock and reminders.** Both need a device the browser cannot reach in the
  background.
- **Financial Coach.** Hidden by `FeatureFlags.FINANCIAL_COACH_ENABLED`, as on Android and iOS.

Offline caching, which Android gets from Room, comes free here from Firestore's IndexedDB
persistence — enabled in `src/firebase.ts` with multi-tab support.
